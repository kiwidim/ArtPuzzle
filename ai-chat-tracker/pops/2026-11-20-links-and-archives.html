Separating chat links from independent archives

Dr. Z and ChatGPT · November 20, 2026

A clickable title did not solve the whole problem. The tracker also needed to distinguish the original chat from the external record that protects the work if provider access changes.

Three links with different jobs

  • Direct link. Opens the user's original conversation.
  • Shareable link. Opens a version intended for another reader and is preferred when available.
  • Archive link. Opens a summary, reconstruction, or verbatim transcript stored outside the chat account.

What remains manual

The app cannot inspect another private tab and recover its URL. The user pastes the direct or shareable link. This limitation is now visible in the interface: a title without a URL opens the Add conversation link form instead of pretending that a destination exists.

The first external archive test

We created a Word summary and a cleaned conversation reconstruction, then uploaded both to a shared OneDrive.Live.com Chat Tracker folder. The similarly named local OneDrive folder remained empty because the shared web folder had not been added to the local synchronized files. That distinction belongs in the tracker documentation.

Accurate archive labels

  • Verbatim transcript requires the complete original conversation.
  • Conversation reconstruction preserves visible messages and rebuilds missing exchanges from available context.
  • Conversation summary records decisions, links, and next actions.

The tracker must preserve this distinction. A reconstruction should never be presented as a provider-signed export.

What this POP proves

A durable conversation record needs both navigation and preservation. The chat link returns to the working thread. The archive link protects the information outside that thread.

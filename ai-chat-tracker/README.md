# AI Chat Tracker

AI Chat Tracker is a provider-neutral conversation ledger for people who work with several AI agents, several chat tabs, or several projects at once. It records where a conversation happened, what was decided, where the work moved next, and where an independent archive was saved.

The first working version was created on November 20, 2026 after Dr. Z and ChatGPT moved between two related ChatGPT conversations and needed a reliable way to preserve continuity. The project currently lives inside the ArtPuzzle repository. Its folder is designed to move later into a standalone repository without changing the record format.

## The problem

AI conversations are often scattered across tabs, accounts, providers, devices, and agents. A useful decision can be difficult to find again. A conversation title is not enough to explain how one thread continues another. Provider history is also not an independent backup: access may change when an account, subscription, workspace, or product changes.

AI Chat Tracker addresses four practical needs:

1. Find the original conversation again.
2. Preserve the decisions and next action when work moves to another conversation or agent.
3. Keep an external summary or transcript outside the chat provider.
4. Exchange a small, portable record among different AI agents.

## What the current app does

The working browser app provides four views.

### Conversation ledger

Each conversation receives a stable identifier such as `CT-20261120-02`. A record can store:

- conversation title;
- provider and agent;
- project or topic;
- start and update times;
- status;
- direct conversation URL;
- shareable conversation URL;
- archive type and archive URL;
- factual summary;
- confirmed decisions; and
- one concrete next action.

When a shareable URL exists, it is preferred for the clickable title. If no URL has been entered, the title opens the editing form so the user can add one.

### Conversation handoffs

The user can record a jump from one conversation to another. The app marks the source record as needing a handoff, creates the target record, and produces a portable JSON handoff packet containing the source, target, context, decisions, and next action.

The packet can be copied into another chat or given to another AI Family agent. It does not require the receiving agent to use the same chat provider.

### Independent backups

The app exports the ledger as JSON or CSV. JSON preserves the complete application state and supports later import. CSV provides a readable table that can be opened in spreadsheet software.

The user can choose a backup reminder interval. The current version can display an in-app reminder and, with permission, a browser notification. It cannot perform an unattended cloud upload by itself.

### AI Family connections

The app displays the portable record schema and accepts a JSON record from another agent. This is the first step toward a universal tracker. Each provider can create the same small record even when it cannot expose a full transcript.

## How it works

The current version is a static browser application.

1. The interface reads the tracker state from browser local storage.
2. Each edit immediately updates that local state.
3. A conversation jump creates a new record and a handoff entry.
4. Export creates a JSON or CSV file on the user's device.
5. Import validates a JSON backup or agent record before adding it to the ledger.
6. Chat and archive links open their external destinations; the tracker does not copy those destinations into its own storage.

No server account or database is required for the current version. This makes the prototype simple and private, but browser local storage is not a durable backup. Regular exports are therefore part of the design rather than an optional extra.

## Conversation links and archive links

The tracker separates two kinds of links because they solve different problems.

| Link | Purpose | Current method |
| --- | --- | --- |
| Direct chat link | Opens the user's original conversation | Entered manually |
| Shareable chat link | Opens a link intended for sharing | Entered manually and preferred by the title |
| Archive link | Opens an external summary or transcript | Entered after the file is saved |

The app cannot discover private URLs from other open ChatGPT tabs. It also cannot create a provider-signed transcript when the full original conversation is unavailable. Archives should therefore use precise labels:

- **Verbatim transcript** when the complete original record is available;
- **Conversation reconstruction** when exchanges are rebuilt from visible context; and
- **Conversation summary** when the file contains decisions, links, and next actions.

## Portable record schema

The current schema uses JSON fields that can be generated by ChatGPT, Claude, Gemini, Copilot, Grok, or another agent.

```json
{
  "ct_schema": "1.2",
  "ct_id": "CT-YYYYMMDD-NN",
  "provider": "ChatGPT",
  "agent": "Agent name",
  "title": "Conversation title",
  "project": "Project or topic",
  "started_at": "ISO-8601 timestamp",
  "updated_at": "ISO-8601 timestamp",
  "summary": "Concise factual summary",
  "decisions": "Confirmed decisions",
  "next_action": "One concrete next action",
  "status": "Active",
  "link": "Optional direct conversation URL",
  "share_link": "Optional shareable URL",
  "archive_type": "Summary and transcript",
  "archive_link": "Stable URL to the saved archive"
}
```

## Privacy and control

- Tracker records remain in the current browser unless the user exports or shares them.
- The app does not read conversations automatically.
- The app does not send records to a server in the current version.
- Export and import are explicit user actions.
- External chat and archive links may have their own access rules.
- A future cloud service must use clear permissions, encryption in transit, access controls, and a documented deletion process.

## Current limitations

- Conversation URLs must be added manually.
- Full transcripts must be supplied by the user or an authorized provider export.
- Browser local storage can be erased by browser cleanup or profile changes.
- Backup reminders work only while the app is open; browser notifications depend on permission.
- The current app does not synchronize across devices.
- Provider-specific automatic capture requires an authorized API, extension, connector, or MCP tool.

## Path from app to plugin

The project can grow in layers without changing the basic record.

1. **Local app:** manual records, handoffs, imports, and exports.
2. **Browser helper:** capture the active chat title and URL with explicit user action.
3. **Provider adapters:** request authorized conversation metadata or exports through supported APIs.
4. **Cloud synchronization:** store encrypted records and archives for access across devices.
5. **MCP service:** expose create, update, search, handoff, and archive operations to participating AI agents.
6. **Independent project:** move this folder and the application source out of ArtPuzzle into a dedicated repository.

## Proposed adapter operations

A provider adapter or MCP service should support a small common interface:

- `create_conversation_record`
- `update_conversation_record`
- `record_handoff`
- `attach_chat_link`
- `attach_archive_link`
- `search_records`
- `export_backup`
- `import_record`

Adapters should report what they can and cannot capture. They must not imply that a reconstruction is a verbatim transcript.

## Project status

Working in the current prototype:

- stable CT identifiers;
- searchable conversation ledger;
- provider and status filters;
- direct and shareable links;
- separate external archive links;
- cross-conversation handoff packets;
- JSON and CSV export;
- JSON import;
- backup reminders; and
- portable AI Family record intake.

Still open:

- provider adapters;
- automatic link capture with explicit permission;
- durable cloud synchronization;
- external archive automation;
- authentication and multi-device access;
- conflict handling; and
- migration to a standalone repository.
